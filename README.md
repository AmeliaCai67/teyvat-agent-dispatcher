# Teyvat Agent Dispatcher

![派遣看板](docs/screenshots/board.png)

**让多个 coding agent 互相派活时，不靠"记得"。**

一个 800 行的薄壳 + 一个消息目录。当一个 agent 唤起另一个 agent 时，
它把"谁派的、派了什么、结果如何"自动留下来 —— 不需要人多做任何一步。

三个文件的最小实现见 [`examples/minimal`](examples/minimal)（零依赖，30 分钟能跑）。
三个真事故见 [踩过的坑](docs/踩过的坑.md)。

---

## 为什么

多 agent 协作最常出问题的地方，其实不是模型不够强，而是**协作不留痕**：

- 谁给谁派了活？派了几轮？没人知道。
- 一个 agent 正在跑，另一个又给它派一条 —— 两条打架。
- 对方有问题没回，发起人已经忘了。
- 事后复盘只剩"印象"，没有证据。

根因是同一句话：**靠记得的规矩，就是会忘。**

所以规矩不写进文档等人遵守，而是做成代码 —— 把安全的路做成最省事的路。

---

## 怎么用

```bash
# 派活（它会自动留档，失败就不执行）
dispatch --from agentA --to agentB --thread <线程id> -- <你要跑的命令>

# 看未读 / 关线程
leyline inbox agentB
leyline close <线程id>
```

调用方无感。派活这件事本身，就是留档。

---

## 一个薄壳做四件事

所有派活经过同一个入口：

**派活前**

1. 提醒发起者：你还有 N 条未关闭的线程
2. 挡在忙的：被派方正在跑就拒绝，并告诉你它在等谁
3. 落档：handoff 先写进地脉（**失败则不执行**）
4. 注入开工须知：把宪章指引 + 待办塞进 prompt

**执行**：命令全量输出落日志

**派活后**

5. report 后落档：退出码 / 耗时 / 输出尾巴（被 kill、超时中断也走 trap 兜底）

---

## 消息格式：一个目录就是一个数据库

留档不引入数据库，**一条消息 = 一个 markdown 文件**：

```
leylines/
  mailbox/           未关闭的线程
  mailbox/archive/   已关闭线程（工具照读 —— 归档是搬家，不是删除）
  dispatch-logs/     每次派活的全量输出
  ledger.md          日报
```

```markdown
---
id: 20261013-1415-001
from: codex
to: claude
type: handoff          # handoff | report | question | close
thread: hero-refactor-20260101
ref: 20261013-1257-001
created: 2026-10-13T06:15:00Z
---

（正文：派了什么、验收标准、相关文件路径）
```

为什么是文件而不是数据库：**它同时是给人看的和给程序读的。**
你把 `mailbox/` 扔进 Obsidian 就能读，用 `grep` 就能查。
**人类可读和机器可读不必二选一。**

## 五个设计判断

代码 800 行谁都能写。下面这几条是踩出来的。

### 1. 留档是派活的副产品，不是额外步骤

如果留档需要人多做一步，它就一定会被跳过。
所以薄壳把留档变成执行的必经之路 —— 你只要派活，留档就已经发生了。

### 2. 失败关闭

留档失败（格式非法、纪律校验拒收、工具缺失）时，**命令不执行**。

反过来（先执行、留档失败就算了）会让留档**在出问题时恰好缺失** ——
而出问题时才是最需要留档的时候。

### 3. 只报警，不处置

看门狗到点只发一条 report 说"已运行 N 秒未完成，请人工确认"，**不杀进程**。

起因是一次真实的误判：有人误判一个正在跑的 agent "僵死"，差点建议杀掉它。
**"看起来停了"和"真的停了"是两件事。误杀不可逆，漏报可补。**

### 4. 宁可漏报，不要误报

"裸跑哨兵"的判据只看时间序（有执行器在跑、且启动时间晚于最后一次留档），
不看"有没有未关闭的 handoff"。

因为后者会被"发起人已离场、没人关的老线程"永久静音 ——
实测地脉里躺着 5 条这样的线程，机制整个失效。

### 5. 边是显式的、可枚举的

"谁可以派给谁"写在一处常量里，非法派活直接拒绝：

```js
const HANDOFF_EDGES = ['pi>claude', 'zcode>codex', 'claude>codex',
                       'codex>claude', 'codex>dsh', 'dsh>claude'];
```

好处是报错时可以把当前合法边列给你 —— 不用背，也绕不开。
而且加边是一次显式的决定：什么时候、为什么、谁批的，都留在修订记录里。

---

## 三条纪律

1. **handoff 只许沿 pipeline 边** —— 防止 agent 互相乱派；
2. **return 只许向后退** —— 下游无权指挥上游改活；
3. **往返 ≥ 6 次熔断升级给人** —— 防止两个 agent 互相踢皮球。

---

## 这套东西没做什么

- **不保证 agent 的输出质量** —— 只管协作的留痕与秩序；
- **不防止人绕过** —— 只让"绕过的成本 > 走正门的成本"；
- **假设 agent 能跑命令** —— 纯聊天式 agent 用不上；
- **没有 UI** —— 所有东西都是文件，用 Obsidian 或 grep 看。
